# راهنمای ویرایش خودکفا — کدوم بخش، کدوم فایل

این راهنما می‌گه هر بخش از سایت رو برای ویرایش باید کجا باز کنی. اکثر تغییرات
محتوایی (متن، عکس، ویدیو، لینک) فقط با ویرایش یکی از فایل‌های `js/data/` انجام
می‌شه — نیازی به دست‌زدن به `index.html` یا فایل‌های دیگه نیست.

✅ هر تغییری که توی فایل‌های `js/data/` بدی، همون لحظه که فایل رو سیو کنی و
صفحه رو رفرش کنی روی سایت دیده می‌شه — هیچ مرحله‌ی اضافه یا Bundle‌ای لازم نیست.

> نسخه‌ی زیباتر و تعاملی‌ترِ همین راهنما رو توی فایل `editing-guide.html` هم
> داری — فقط دوبار کلیکش کن تا توی مرورگر باز بشه.

## ۱. محتوای هر بخش، مال کدوم فایله

| بخش سایت | فایلی که باید ویرایش کنی | نکته |
|---|---|---|
| مهارت‌ها (Skills) | `js/data/skills.js` | اسم مهارت + درصد |
| پروژه‌ها (Projects) | `js/data/projects.js` | عنوان، توضیح، تگ‌ها، لینک گیت‌هاب/دمو، عکس، **و حالا ویدیو** |
| دستاوردها/نشان‌ها (Achievements / Badges & Milestones) | `js/data/achievements.js` | |

| آخرین فعالیت‌ها (Latest Activity) | `js/data/latest-activity.js` | |
| مهارت‌ها و تجربه (Skills & Experience — ابزار/تایم‌لاین/گواهی) | `js/data/experience.js` | سه بخش تو یه فایل: tools / timeline / certs |

هر فایل بالای خودش یه کامنت داره که دقیقاً می‌گه چی رو ویرایش کن.

## ۲. برای حذف یه آیتم (مثلاً یه پروژه یا پست)

توی فایل مربوطه (مثلاً `js/data/projects.js`)، کل بلوک `{ ... }` مربوط به همون آیتم
رو با ویرگولش پاک کن. مثلاً برای حذف یه پروژه:

```js
{
  cat: 'plc',
  titleEn: '...',
  ...
},   ← این کل بلوک رو با کاما پاک کن
```

## ۳. برای اضافه کردن یه آیتم جدید

یه بلوک `{ ... }` شبیه بقیه رو کپی کن، بچسبون زیرش (با کاما جدا کن)، و مقادیرش
رو عوض کن. ترتیب و اسم فیلدها باید دقیقاً مثل بقیه‌ی آیتم‌ها بمونه.

## ۴. افزودن عکس

**پروژه‌ها** — عکس رو بریز توی `assets/img/projects/`، بعد توی `js/data/projects.js`:
```js
image: 'assets/img/projects/اسم-عکس.jpg'
```

**پست‌های فید** — عکس رو بریز یه‌جایی مثل `assets/img/posts/`، بعد توی `js/data/posts.js`:
```js
image: 'assets/img/posts/اسم-عکس.jpg'
```

اگه `image` نذاری، همون ظاهر پیش‌فرض (گرادیان + آیکون) نشون داده می‌شه — هیچ‌وقت چیزی خراب نمی‌شه.

## ۵. افزودن ویدیو — فقط با لینک، بدون آپلود فایل

هم توی `js/data/projects.js` و هم `js/data/posts.js`، یه فیلد `video` اضافه کن:
```js
video: 'https://youtu.be/xxxxxxx'
```
لینک یوتیوب، آپارات، یا لینک مستقیم یه فایل mp4 قبول می‌شه.

- **توی پروژه‌ها:** یه دکمه‌ی «ویدیو» کنار GitHub/Demo ظاهر می‌شه که با کلیک، ویدیو رو تمام‌صفحه پخش می‌کنه.
- **توی پست‌ها:** ویدیو مستقیم داخل خودِ پست embed می‌شه.

## ۶. ویژگی‌های جدید سایت (جستجو، فیلتر، تستیمونیال، رزومه، Case Study، PWA، SEO، RSS، اسکرول‌ریویل، تم‌ها، رزرو)

همه‌ی این ویژگی‌ها توی `js/features.js` + `css/features.css` پیاده‌سازی شدن و
کاملاً بدون بک‌اند/سرور کار می‌کنن. برای هرکدوم فقط کافیه فایل‌های `js/data/`
رو ویرایش کنی؛ نیازی به دست‌زدن به `js/features.js` نیست.

### ۶.۱ جستجوی سراسری (Global Search)
یه دکمه‌ی جستجو بالای نویگیشن اضافه شده (یا کلید میانبر `Ctrl+K` / `Cmd+K`).
بین **پروژه‌ها**، **کتابخانه‌ی کد** و **مقالات بلاگ** هم‌زمان جستجو می‌کنه —
مستقیم از `js/data/projects.js`، `js/data/codes.js` و `js/data/blog-posts.js`.
چیزی برای تنظیم نیست؛ هر آیتم جدیدی که به این فایل‌ها اضافه کنی خودکار قابل
جستجو می‌شه.

### ۶.۲ فیلتر و مرتب‌سازی پروژه‌ها
بالای بخش «Projects» یه نوار فیلتر/مرتب‌سازی اضافه شده (وقتی حداقل ۲ پروژه
داشته باشی ظاهر می‌شه). دسته‌بندی‌ها (تب‌ها) خودکار از روی فیلد `cat` توی
`js/data/projects.js` ساخته می‌شن. برای مرتب‌سازی «جدیدترین» و «محبوب‌ترین»،
این دو فیلد اختیاری رو به هر پروژه اضافه کن:
```js
dateISO: '2025-06-01',   // برای «جدیدترین»
popularity: 42,          // یه عدد دلخواه، برای «محبوب‌ترین»
```
ویدیوها (بخش Reels) از قبل فیلتر/مرتب‌سازی/جستجوی خودشون رو دارن — چیز جدیدی
لازم نبود.

### ۶.۳ نظرات و توصیه‌نامه‌ها (Testimonials)
فایل `js/data/testimonials.js` رو ویرایش کن. اگه این فایل خالی باشه، کل بخش
«Testimonials» خودکار مخفی می‌شه — سایت خراب نمی‌شه.

### ۶.۴ دانلود رزومه (PDF)
فایل PDF رزومه رو بریز توی `assets/` (مثلاً `assets/resume.pdf`)، بعد توی
`js/data/site-config.js`:
```js
cv: 'assets/resume.pdf',
```
تا وقتی این فیلد خالیه، دکمه‌ی «Download Full CV» غیرفعال نشون داده می‌شه و
یه تولتیپ راهنما نشون می‌ده.

### ۶.۵ صفحه‌ی جزئیات پروژه (Case Study)
زیر جزئیات هر پروژه توی چرخ‌فلک، یه دکمه‌ی «Case Study» اضافه شده که یه
مودال با جزئیات کامل‌تر باز می‌کنه. برای محتوای بیشتر، این فیلدهای اختیاری رو
به هر پروژه توی `js/data/projects.js` اضافه کن:
```js
fullDescEn: 'A longer, more detailed English description...',
fullDescFa: 'توضیح کامل‌تر فارسی...',
gallery: ['assets/img/projects/p1-1.jpg', 'assets/img/projects/p1-2.jpg']
```
اگه نذاری‌شون، مودال از همون `descEn`/`descFa` استفاده می‌کنه و گالری مخفی می‌مونه.

### ۶.۶ تبدیل به PWA (نصب روی موبایل + کارکرد آفلاین)
فایل `sw.js` (Service Worker) اضافه شده و صفحه‌ی اصلی و فایل‌های CSS/JS رو
کش می‌کنه تا سایت بدون اینترنت هم باز بشه. اگه بعداً فایل‌های اصلی سایت
(CSS/JS) رو عوض کردی و می‌خوای کاربرها نسخه‌ی جدید رو بگیرن، همین کافیه:
توی `sw.js`، مقدار `CACHE_VERSION` رو یکی زیاد کن (مثلاً `'v1'` → `'v2'`).
نصب روی موبایل (Add to Home Screen) از قبل با `js/pwa-manifest.js` فعال بود؛
چیزی عوض نشده.

### ۶.۷ سئو (SEO)
- متادیتای `og:`/`twitter:`/`canonical`/JSON-LD به `<head>` اضافه شد.
- `sitemap.xml` و `robots.txt` توی ریشه‌ی سایت ساخته شدن.
- **مهم:** توی هر دو فایل بالا و توی `<link rel="canonical">` و
  `<link rel="alternate" type="application/rss+xml">` داخل `index.html`،
  آدرس `https://your-domain.example` رو با آدرس واقعی سایتت (بعد از دیپلوی
  روی Netlify/GitHub Pages/دامنه‌ی شخصی) جایگزین کن.

### ۶.۸ RSS فید برای بلاگ
هر وقت `js/data/blog-posts.js` رو ویرایش کردی (پست اضافه/حذف/ویرایش کردی)،
این دستور رو توی ترمینال، توی پوشه‌ی اصلی سایت اجرا کن:
```bash
python3 tools/generate-rss.py
```
یه فایل `rss.xml` جدید می‌سازه. آدرس دامنه‌ی داخل این اسکریپت
(`tools/generate-rss.py`، متغیر `SITE_URL`) رو هم مثل بالا با آدرس واقعی
سایتت جایگزین کن.

### ۶.۹ اسکرول‌ریویل (Scroll Reveal)
خودکاره — همه‌ی بخش‌های اصلی صفحه با اسکرول به آرومی fade+slide می‌شن.
چیزی برای تنظیم نیست. اگه کاربر تنظیم «کاهش انیمیشن» (Reduced Motion) رو
توی سیستمش فعال کرده باشه، این افکت خودکار غیرفعال می‌شه.

### ۶.۱۰ تم‌های رنگی بیشتر
کنار دکمه‌ی روشن/تاریک، یه آیکون پالت رنگ اضافه شده که ۵ تم رو نشون می‌ده:
Amber (پیش‌فرض)، Teal، Crimson، Violet، Arctic. انتخاب کاربر توی مرورگرش
ذخیره می‌شه. برای تغییر رنگ‌های هرکدوم، توی `css/features.css` دنبال
`body.theme-teal` (یا crimson/violet/arctic) بگرد.

### ۶.۱۱ رزرو جلسه با Calendly
توی `js/data/site-config.js`:
```js
calendlyUrl: 'https://calendly.com/your-username/30min',
```
وقتی این فیلد رو پر کنی، بخش «Book a Meeting» خودکار به‌جای فرم نمایشی فعلی،
یه Calendly embed واقعی نشون می‌ده — بدون نیاز به هیچ بک‌اندی. تا وقتی خالیه،
همون فرم نمایشی فعلی دست‌نخورده می‌مونه.

### ۶.۱۲ چت‌بات بخون PDF/HTML (خواندن کتابخانه‌ی PDF)
چت‌بات آفلاین سایت حالا می‌تونه متن فایل‌های بخش «کتابخانه‌ی PDF» رو بخونه
و توی جواب‌هاش ازش استفاده کنه — کاملاً سمت مرورگر کاربر، بدون بک‌اند.
دو نوع فایل پشتیبانی می‌شه:
- **PDF** — با کتابخانه‌ی Mozilla pdf.js
- **HTML** — گاهی به‌جای PDF، یه صفحه‌ی HTML ساده (مثلاً یه گزارش یا
  دیتاشیت وب‌محور) می‌خوای بذاری؛ این حالت هم پشتیبانی می‌شه، بدون نیاز
  به pdf.js (فقط با `fetch` ساده متن صفحه خونده می‌شه).

نوع فایل خودکار و فقط از روی پسوندش (`.pdf` در برابر `.html`/`.htm`)
تشخیص داده می‌شه — کاری نیست که جدا مشخص کنی.

**برای این‌که چت‌بات یه سند جدید (PDF یا HTML) رو یاد بگیره:**
1. فایل رو بریز توی پوشه‌ی `assets/pdfs/` (مثلاً `assets/pdfs/catalog.pdf`
   یا `assets/pdfs/catalog.html`).
2. توی `js/data/pdfs.js`، به همون آیتم فیلد `file` رو اضافه کن:
   ```js
   {
     titleEn: 'Product Catalog',
     titleFa: 'کاتالوگ محصولات',
     descEn: '...',
     descFa: '...',
     preview: 'assets/pdfs/catalog.html',
     dl: 'assets/pdfs/catalog.html',
     file: 'assets/pdfs/catalog.html'   // 👈 می‌تونه .pdf یا .html باشه
   }
   ```
3. همین! لازم نیست هیچ کد دیگه‌ای رو دست بزنی. سایت خودکار موقع بارگذاری
   (یا اولین بار که کاربر پنجره‌ی چت رو باز می‌کنه)، متن این فایل رو
   استخراج می‌کنه و به دانش چت‌بات اضافه می‌کنه. آیکون کارت هم خودکار
   بین PDF و HTML فرق می‌کنه.

**نکات مهم:**
- اگه یه آیتم فیلد `file` نداشته باشه (فقط لینک `preview`/`dl` خارجی
  داشته باشه)، چت‌بات بی‌سروصدا نادیده‌اش می‌گیره — هیچ خطایی نمی‌ده.
- متن هر سند یه‌بار پردازش و توی مرورگر کاربر (`localStorage`) کش می‌شه؛
  بار بعد که همون کاربر سایت رو باز کنه، دیگه دوباره پردازش نمی‌شه.
  اگه محتوای یه سند رو عوض کردی ولی اسم فایلش همون موند، برای این‌که
  کش قدیمی پاک بشه، یا اسم فایل رو عوض کن یا توی
  `js/chatbot/pdf-knowledge.js` مقدار `CACHE_VERSION` رو یکی زیاد کن.
- برای اسناد PDF خیلی حجیم، فقط ۶۰ صفحه‌ی اول خونده می‌شه (قابل تنظیم با
  `MAX_PAGES` توی همون فایل).
- کتابخانه‌ی pdf.js (نسخه‌ی ۳.۱۱.۱۷۴) از CDN فقط وقتی واقعاً لازم بشه
  (یعنی یه فایل `.pdf` با فیلد `file` وجود داشته باشه) لود می‌شه؛ برای
  فایل‌های HTML اصلاً لود نمی‌شه. پس روی سرعت اولیه‌ی سایت تأثیری نمی‌ذاره.

## اگه یه جا گیر کردی

بفرست)، همون فایل رو کامل می‌کنم و نسخه‌ی آماده‌ی آپلود رو برمی‌گردونم.
