# رودمپ پروژه

وضعیت فعلی: سایت کار می‌کنه، محتوا داده‌محوره، ولی بار فنی (technical debt) داره.
این رودمپ از «الان قابل انتشاره» شروع می‌شه و تا «پروژه‌ی حرفه‌ای و قابل‌نگهداری» می‌ره.
هر فاز مستقل قابل انجامه — لازم نیست همه رو پشت‌سر هم بری.

---

## فاز ۰ — بازسازی ساختار ✅ انجام شد

CSS و JS از فایل‌های چندهزارخطی به ماژول‌های شماره‌گذاری‌شده تقسیم شدن،
دو Service Workerِ متداخل به یکی کاهش پیدا کرد، مسیرهای شکسته اصلاح شدن و
اسکریپت باندل‌سازی اضافه شد. جزئیات کامل در `CHANGELOG.md`.

## فاز ۱ — آماده‌ی انتشار 🔴 اولویت بالا · ۱ تا ۲ روز

کارهای کوچیک ولی مسدودکننده. تا این‌ها انجام نشه، سایت واقعاً منتشرشدنی نیست.

| کار | چرا |
|---|---|
| جایگزینی `https://your-domain.example` با دامنه‌ی واقعی در `index.html`، `sitemap.xml`، `rss.xml`، `robots.txt` | الان canonical و RSS به دامنه‌ی جعلی اشاره می‌کنن؛ گوگل نمی‌تونه ایندکس درست بکنه |
| اضافه کردن `assets/resume.pdf` | دکمه‌ی دانلود رزومه ۴۰۴ می‌ده |
| اضافه کردن `assets/img/background/bg.jpg` | حالت پس‌زمینه‌ی تصویری در `site-config.js` بدون فایل کار نمی‌کنه |
| ساخت `assets/img/og-cover.png` (۱۲۰۰×۶۳۰) و افزودن `og:image` | الان لینک سایت در تلگرام/لینکدین بدون تصویر پیش‌نمایش می‌افته |
| انتشار روی Cloudflare Pages یا GitHub Pages با خروجی `dist/` | HTTPS، CDN و دامنه‌ی رایگان |
| تست روی یک گوشی واقعی (اندروید + iOS Safari) | سایت انیمیشن سنگین داره؛ شبیه‌ساز کافی نیست |

**خروجی فاز:** سایت روی دامنه‌ی واقعی بالاست و در گوگل ایندکس می‌شه.

## فاز ۲ — سلامت CSS 🟠 اولویت متوسط · ۳ تا ۵ روز

مشکل اصلی: `20-theme-industrial.css` یک «لایه‌ی وصله» است که با **۹۳ تا
`!important`** روی استایل‌های پایه می‌نویسه. یعنی هر تغییر کوچیک در فایل‌های
اصلی ممکنه هیچ اثری نداشته باشه و تو ندونی چرا.

1. **ادغام تدریجی تم**: برای هر بلاک در `20-theme-industrial.css` مقدار نهایی رو
   مستقیم داخل فایل اصلی مربوطه بنویس و `!important` رو بردار. بخش‌به‌بخش، و بعد
   از هر بخش چشمی تست کن. هدف: رسیدن به زیر ۱۰ تا `!important`.
2. **حذف ۲۳ سلکتور تکراری** بین `main.css` قدیمی و لایه‌ی تم (مثل `.pdesc`،
   `.skills-grid`، `.footer-grid` که هرکدوم ۳ بار تعریف شدن).
3. **استفاده از `@layer`**: `@layer tokens, base, components, theme, utilities;`
   ترتیب اولویت رو صریح می‌کنه و دیگه به `!important` نیاز نیست.
4. **یکدست‌سازی توکن‌ها**: همه‌ی رنگ‌ها، فاصله‌ها و شعاع گوشه‌ها فقط از
   `01-tokens.css` بیان — الان مقادیر هاردکد پراکنده‌ست.
5. **حذف CSS بلااستفاده** با PurgeCSS. حدس: ۳۰ تا ۴۰ درصد از ۱۶۹ کیلوبایت CSS
   روی صفحه استفاده نمی‌شه.

**خروجی فاز:** تغییر یک رنگ در یک جا، همه‌جای سایت اعمال می‌شه.

## فاز ۳ — جاوااسکریپت ماژولار 🟠 اولویت متوسط · ۱ تا ۲ هفته

الان ۲۳۱ متغیر و تابع سراسری داری و ۵۴ تا `onclick` مستقیم داخل HTML.
تا وقتی این‌طوره، نه می‌شه تست نوشت، نه می‌شه CSP امن گذاشت.

1. **حذف `onclick`های inline** → `addEventListener` با event delegation و
   `data-action="..."`. این تنها راه فعال‌کردن `Content-Security-Policy` سخت‌گیرانه‌ست.
2. **مهاجرت به ES Modules**: هر فایل `export`/`import` بشه و `<script type="module">`.
   چیزی که واقعاً باید سراسری بمونه، صریح روی `window` گذاشته بشه.
3. **باندلر واقعی** (esbuild یا Vite) جای `build/build.js` ساده. الان باندل خام
   ۵۱۸ کیلوبایته و minify نمی‌شه؛ با esbuild حدود نصف می‌شه.
4. **جدا کردن state از DOM**: داده‌های ذخیره‌شده در مرورگر (لایک، بازدید،
   watch-later، تاریخچه) الان پراکنده‌ان — یک ماژول `storage.js` با
   try/catch سراسری و یک اسکیمای مشخص.
5. **مدیریت خطا**: `window.onerror` که خطاها رو لاگ کنه، تا مثل الان یک خطای
   انیمیشن باعث از کار افتادن بی‌صدای بخش دیگه‌ای نشه.

**خروجی فاز:** می‌تونی بدون ترس کد رو عوض کنی.

## فاز ۴ — کارایی و سرعت 🟡 · ۳ تا ۵ روز

سایت الان به سه دامنه‌ی خارجی وابسته‌ست (Google Fonts، Font Awesome، AOS).
هر کدوم یک DNS + TLS جدا و یک نقطه‌ی شکست اضافه‌ست.

| کار | صرفه‌جویی تقریبی |
|---|---|
| میزبانی محلی فونت‌ها (Vazirmatn + Space Grotesk + JetBrains Mono) با `font-display: swap` و زیرمجموعه‌سازی (subset) | حذف ۲ دامنه، ۲۰۰ تا ۴۰۰ میلی‌ثانیه |
| جایگزینی Font Awesome کامل با SVG sprite فقط از آیکون‌های استفاده‌شده | حدود ۷۰ کیلوبایت |
| حذف AOS و استفاده از `IntersectionObserver` خودت (کد scroll-reveal رو از قبل داری) | حدود ۱۵ کیلوبایت + یک دامنه |
| `loading="lazy"` روی iframeها و عکس‌ها (الان فقط ۲ تا داره) | لود اولیه‌ی سبک‌تر |
| احترام به `prefers-reduced-motion` در کل موتور سینمایی، نه فقط CSS | باتری و CPU موبایل |
| تعریف بودجه‌ی عملکرد: LCP زیر ۲.۵ ثانیه، JS زیر ۱۵۰ کیلوبایت gzip | جلوگیری از بازگشت به عقب |
| اضافه‌کردن Lighthouse CI به GitHub Actions | هر PR امتیاز می‌گیره |

## فاز ۵ — کیفیت و خودکارسازی 🟡 · ۳ تا ۴ روز

1. **ESLint + Prettier + Stylelint** با یک کانفیگ ساده و `npm run lint`.
2. **تست دود با Playwright**: صفحه باز بشه، خطای کنسول نده، هر ۱۸ بخش رندر بشن،
   چت‌بات جواب بده، تعویض زبان کار کنه. ۵ تا تست کافیه و ۹۰٪ رگرسیون‌ها رو می‌گیره.
3. **GitHub Actions**: روی هر push → lint، build، تست، deploy خودکار `dist/`.
4. **نسخه‌گذاری خودکار Service Worker** در همون اکشن (الان دستیه).
5. **بررسی دسترس‌پذیری (a11y)**: کنتراست رنگ‌ها، فوکوس صفحه‌کلید روی
   ۴۱ دکمه، و `aria-label` برای دکمه‌های فقط‌آیکونی.

## فاز ۶ — محتوا و رشد 🟢 · مستمر

1. **بلاگ واقعی**: هر پست یک فایل Markdown در `content/posts/`، و
   `tools/generate-rss.py` (که از قبل داری) هم HTML و هم RSS رو بسازه.
   الان پست‌ها داخل JS هاردکدن.
2. **i18n درست**: ۲۰۹ تا `data-fa` پراکنده داخل HTML → یک `i18n/fa.json` و
   `i18n/en.json`. اضافه‌کردن زبان سوم بعدش رایگان می‌شه.
3. **فرم تماس واقعی** با Formspree یا Cloudflare Worker (الان فقط `mailto:` می‌سازه).
4. **آنالیتیکس سبک و بدون کوکی** (Plausible یا Cloudflare Web Analytics).
5. **جایگزینی داده‌های نمونه** با پروژه‌ها، ویدیوها و نظرات واقعی — مهم‌ترین
   کار از نظر تأثیر، و ربطی هم به کد نداره.
